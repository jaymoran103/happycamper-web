Suggest a revised set of commits for the entire repo: My goal is to always use plainly worded conventional commits, intended to express the changes to a human rather than spewing jargon only an implementing agent would understand. We can come up with whatever commit categories and scope best suit the project, I'm not settled on the exact conventions for these automated iterations. The goal is never to fool a user that everything was written by a human, the objective is interpretability. It's a widespread problem for claude code to ramble excessively in every docs/vc surface it touches, effectively gatekeeping repo understanding from users. Beyond the title line and an optional follow up line, all further details in a commit message should be simple, accessible bullets. If too many code changes were made to summarize concisely in 3 bullets, It's a sign the change should probably be broken into a series of smaller commits, ensuring that the version controlled logs can be easily understood and reasoned about by a developer without prior experience with the project. Once we're happy with the convention, this can be standardized here as conventions.md, or as an additional section in the agents markdown.

On additional footers and helpful sounding fluff: I usually avoid extra trailing tags. Agents always want to commit messages with links and fluff, I feel strongly that this should be human centric and easy to write without an external tool or pasted structure. You should not have to choose between a consistent commit style and being able to quickly track thoughts by hand.
